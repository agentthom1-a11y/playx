# PlayX × Mixxx 2.4+ — experimental live setup

**Use at your own risk; rehearse before playing for an audience.** PlayX does not operate Mixxx as a DAW plugin. It sends MIDI messages to a Mixxx controller mapping and receives Mixxx beat/status feedback.

## Windows setup

1. Install [Mixxx](https://mixxx.org/) and [loopMIDI](https://www.tobias-erichsen.de/software/loopmidi.html).
2. Create a loopMIDI virtual MIDI port named `PlayX`.
3. Copy **both** `mixxx/PlayX.midi.xml` and `mixxx/PlayX-scripts.js` into Mixxx's user `controllers` directory. In Mixxx, Preferences → Controllers → select the PlayX virtual port and the **PlayX Agent MIDI** preset; enable it and apply.
4. Add your music to Mixxx and analyze BPM/beatgrids. Load two tracks. Route Channel 1 to the left of the crossfader and Channel 2 to the right; begin playing deck 1. Keep deck 2 paused with a track loaded.
5. Test the MIDI bridge in a non-public environment:

```powershell
playx mixxx-ports
playx mixxx-status --port "PlayX"
playx mixxx-beatmix --port "PlayX" --bars 8 --style smooth --lead-beats 16
```

`mixxx-beatmix` requires **both decks loaded** and **incoming beat feedback** (CC70/71, generated by the PlayX controller script). It reports errors if either is missing. It waits for 16 Mixxx beats from the currently playing deck, then commands the incoming deck to sync and play, and moves the crossfader based on continuing beat feedback. `--from-deck 2` reverses direction. Its 4/8/16/32 bars are counted from the start of the mix, **not** from guaranteed downbeats or 4-bar musical phrases. Mixxx's `beat_active` signal is a beat marker, not a bar/downbeat classifier.

## Selected-row loading and queueing

```powershell
playx mixxx-load-selected --port "PlayX" --deck 2
playx mixxx-load-next --port "PlayX" --deck 2
```

`load-selected` loads the **currently highlighted Mixxx library row** into the named deck. `load-next` sends a MoveDown then loads that new row; it requires the Mixxx window *and tracks table* to have keyboard focus, an ordered curated playlist, and sufficient time for selection to update. **Inspect the track name and waveform after every load.** There is no verified load-by-path MIDI API in Mixxx 2.5. In particular this is not safe for unattended autonomous set selection.

## Fallback without beat feedback

```powershell
playx mixxx-transition --port "PlayX" --seconds 8 --style smooth
```

The fallback is a wall-clock transition and **does not beatmatch or synchronize itself**. In both live modes the style names affect **only the crossfader curve**, not on-deck EQ, delay effects, stems, or filter automation.

## Protocol

| Message | Function |
|---|---|
| CC16 | Crossfader position, 0–127 |
| Note 20 / 21 | Load selected library row into deck 1 / deck 2 |
| Note 22 / 23 | Start incoming deck 2 / deck 1 with keylock |
| Note 24 / 25 | Enable sync on deck 2 / deck 1 |
| Note 29 | Move library selection down (focus required) |
| Note 30 | Request current loaded-status feedback |
| CC70 / CC71 | Beat pulse from deck 1 / deck 2 (`127` on each forward beat) |
| CC72 / CC73 | Deck 1 / 2 track-loaded status (`0` or `127`) |

The protocol is scoped to one virtual port and does not implement secure remote networking. Keep Mixxx and the bridge on the same workstation. Pause and take manual control whenever alignment is uncertain. PlayX cannot guarantee glitch-free playback on all systems.
